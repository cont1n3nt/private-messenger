# Определения
**lazy** определяет стратегию загрузки связанных данных (когда алхимия должна выполнить запрос для получения связанных объектов)

**cascade** определяет, как операции над родительским объектом распространяются на связанные объекты (в памяти ORM, не в БД!)

**foreign_keys** явно указывает, какие внешние ключи использовать для связи, когда между таблицами есть несколько отношений

**back_populates** связывает два relationship, указывая на обратное свойство в связанном классе (обеспечивает двухстороннюю синхронизацию)


# Типы Relationship (связей)
| Тип связи | Описание | Пример из кода |
| :--- | :--- | :--- |
| One-to-Many | Один объект связан со многими | `User` → `sessions` (один пользователь — много сессий) |
| Many-to-One | Обратная сторона One-to-Many | `Session` → `user` (много сессий — один пользователь) |
| One-to-One | Редкое, через `uselist=False` | `User.profile` (один пользователь — один профиль) |
| Many-to-Many | Через промежуточную таблицу | Например, пользователи → группы (требует `secondary`) |


# Lazy
| Вид lazy | Значение | Поведение | Когда использовать | Пример |
| :--- | :--- | :--- | :--- | :--- |
| `"select"` (по умолчанию) | Загружает связанные объекты отдельным запросом при первом обращении | Когда связанных объектов много и они нужны не всегда | `User.sessions` |
| `"joined"` | Загружает связанные объекты через LEFT JOIN в одном запросе | Когда связанные объекты почти всегда нужны, и их немного | `Session.user` (каждая сессия почти всегда требует пользователя) |
| `"selectin"` | Загружает через отдельный запрос с IN (оптимален для Many-to-Many) | Когда связанных объектов много, но связь Many-to-Many | `Message.sender` -z эффективнее для списка сообщений |
| `"subquery"` | Отдельный запрос с подзапросом | Редко, в особых случаях | - |
| `"raise"` | Бросает исключение при попытке доступа (запрещает lazy-загрузку) | Для строгого контроля, чтобы избежать N+1 | - |
| `"noload"` | Никогда не загружает, всегда пусто | Когда связанные данные не нужны | - |
